# 插件市场规范与准入政策

本文档说明了发布至 MicYou 官方插件市场的规范要求、开源许可证政策与安全审核流程。

## 1. 许可证政策与插件例外条款

MicYou 项目主代码采用 GNU GPLv3 许可证，并附加官方插件例外条款（**MicYou Plugin Exception v1.0**）。

### 1.1 豁免范围
- 插件开发者通过 MicYou 官方提供的 Plugin API 与 Host API 开发独立插件时，**不受 GPLv3 许可证的传染性约束**。
- 非商业用途的独立插件可以自由选择宽松开源许可证（如 MIT、Apache-2.0、BSD）或闭源私有许可证。

### 1.2 商业化政策
- 任何通过 MicYou 插件进行付费销售、商业订阅或商业分发的行为，需事先取得 MicYou 项目版权方的书面授权或许可。
- 企业内部自用且不对外公开发布分发的工具插件不受此商业许可限制。

## 2. 官方插件市场准入要求

提交至官方插件市场（MicYou Plugin Marketplace）的插件需满足以下条件之一：

1. **开源准入**：插件源代码完全公开，且采用与主流生态兼容的自由/开源许可证（如 MIT、Apache-2.0、GPL-3.0 等）。
2. **审查准入**：闭源或特定商业插件需通过官方安全团队的合规性与代码安全性审查。

### 本地化展示建议

市场根据用户客户端语言自动展示插件信息：
- 在 `plugin.json` 中配置 `nameI18n` 和 `descriptionI18n`（按 BCP-47 语言标签映射）。
- 提交至官方市场的插件建议至少提供简体中文（`zh-CN`）与英文（`en`）两种语言描述。

## 3. 安全与隐私规范

- **权限最小化原则**：插件仅能申请其实际功能所必需的 capabilities 权限，严禁过度申请敏感权限。
- **音频隐私与数据安全**：严禁在未经用户明确知情与同意的情况下上传、记录或窃取用户麦克风音频流及系统剪贴板内容。
- **文件沙箱约束**：文件读写必须限定在宿主分配的插件私有目录内，禁止试图穿透沙箱。
- **严禁恶意代码**：严禁包含任何挖矿、后门、木马、外挂注入或破坏宿主系统稳定性的行为。

## 4. 提交审核流程

1. 开发者在自身 GitHub 仓库完成插件开发并通过 CI 编译打包，将产物发布至 GitHub Release。
2. Fork 官方市场索引仓库（[MicYou-Plugins](https://github.com/MicYou-Dev/MicYou-Plugins)），在 `plugin/<plugin-id>/` 目录下添加 `plugin.json` 与安装包下载链接。
3. 提交 Pull Request，触发自动化 CI 流水线对清单格式、签名与能力声明进行语法校验。
4. 官方审核团队进行安全与合规审查，确认通过后合并并同步至线上市场索引。
