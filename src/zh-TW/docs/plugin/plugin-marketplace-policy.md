# 插件市集開發者規範與准入政策

本文檔規定了發布至 MicYou 官方插件市集的插件准入要求、授權政策與安全審核流程。

## 1 授權政策與例外條款

MicYou 遵循帶有插件例外的 GNU GPLv3 授權條款（MicYou Plugin Exception v1.0）。

### 1.1 豁免範圍
- 插件開發者可透過 MicYou 官方 Plugin API 與 Host API 編寫獨立插件，不受 GPLv3 傳染限制。
- 非商業用途的獨立插件可自由採用任意開源協議（如 MIT、Apache-2.0）或閉源專有授權。

### 1.2 商業化插件政策
- 任何透過 MicYou 插件進行付費銷售、商業授權或訂閱營利的行為，均需事先取得 MicYou 版權方的書面授權或商業許可。
- 企業內部私有開發且不進行公開商業分發的工具插件不受商業許可限制。

## 2 官方插件市集准入要求

發布至官方插件市集（MicYou Plugin Marketplace）的插件需滿足以下條件之一：

1. **開源准入**：插件原始碼完全公開，且採用與 GPLv3 相容的自由/開源授權條款（如 GPL-3.0、MIT、Apache-2.0 等）。
2. **審查准入**：閉源或商業化插件需經過官方安全與合規審查，並獲得上架許可認證。

### 2.1 本地化展示規範

市集頁面支援按客戶端介面語言展示插件名稱與說明：
- Manifest 中若設定了 `nameI18n` 與 `descriptionI18n`（按 BCP-47 標籤對應），市集將優先呈現對應語言，缺失時回退至基礎 `name` 與 `description`。
- 新提交至官方市集的插件建議至少包含 `zh`（或 `zh-CN`）與 `en` 兩種語言設定。

## 3 安全與合規規範

- **權限最小化**：插件 manifest 必須如實宣告所需能力（capabilities），嚴禁申請未實際使用的敏感權限。
- **網路與隱私**：涉及網路請求或使用者資料採集的插件必須在文檔中明確告知用途，嚴禁暗中上傳使用者音訊或敏感資訊。
- **沙箱與儲存**：檔案讀寫必須限定在宿主分配的插件獨立目錄內。
- **禁止惡意行為**：嚴禁包含任何挖礦、惡意後門、劫持系統裝置或繞過宿主安全機制的程式碼。

## 4 提交流程與分發架構

1. 開發者在自身程式碼倉庫完成開發並透過 CI 打包構建產物發布至 GitHub Release。
2. 在官方市集索引倉庫（[MicYou-Plugins](https://github.com/MicYou-Dev/MicYou-Plugins)）提交 Pull Request，登記 `plugin.json` 元資料與發布下載連結。
3. 自動化 CI 校驗清單格式、簽章與能力宣告。
4. 人工審核團隊進行程式碼安全與授權審查，合規後合併並同步至市集索引。
