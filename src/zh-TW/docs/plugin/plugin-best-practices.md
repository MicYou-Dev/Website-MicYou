# 插件最佳實踐與擴充架構

本文件介紹 MicYou 插件系統的架構設計考量、行動端擴充路線、API 相容演進原則及安全與效能規範。

## 1. 行動端擴充路線：協定統一與輕量實作

為了在未來將插件能力平滑拓展至 Android 行動端，MicYou 採用「**協定統一 + 實作解耦**」的設計原則，避免照搬重型動態插件化框架。

### 為什麼避免重型插件化框架？

在 Android 生態中，RePlugin、Shadow 等框架主要面向大型應用的組件熱修復與頁面動態化，對 MicYou 而言屬於過度設計：

- **體積與打包開銷**：傳統框架體積臃腫、侵入性強，不適合輕量級音訊工具。
- **目標不相符**：MicYou 插件的核心訴求是音訊 DSP 節點、事件訂閱與跨端通訊，而非 Activity 頁面跳轉與組件插拔。
- **安全與權限衝突**：動態載入未經驗證的任意 APK 與插件系統的沙箱能力授權模型相衝突。
- **系統升級維護成本**：重型框架極易受 Android 系統版本及 Gradle 插件升級影響。

### 三階段演進路線

```text
階段一：協定對齊 ──► 階段二：輕量執行階段 ──► 階段三：跨端全互通
```

1. **階段一：協定對齊（核心）**  
   - 行動端實作統一的 `plugin.json` 清單解析與校驗。
   - 在行動端 TCP 控制通道中接入 Protobuf `PluginMessage` 編解碼。
   - 實作輕量級的 `PluginBus`，打通行動端與桌面端的雙向訊息往返。

2. **階段二：輕量執行階段**  
   - **WASM（優先）**：編譯嵌入純 Rust 的 `wasmi` 直譯器，享有天然的記憶體與燃料沙箱。
   - **受信 Native (.so)**：面向即時音訊 DSP，透過 JNI 暴露統一 C ABI，僅允許載入受信任的預編譯演算法函式庫。
   - **輕量 DEX**：透過 `PathClassLoader` 隔離載入純邏輯工具插件。

3. **階段三：跨端全互通**  
   - 實作兩端插件的自動發現與清單廣播。
   - 落地典型應用場景（如手機採集感測器資料 → 電腦端演算法處理 → 結果即時回傳）。

## 2. 版本相容與解耦策略

為了保證宿主與插件在長期演進中互不破壞，系統設計了多層相容屏障：

- **Host API 版本協商**：宿主支援向前相容的 API 版本區間（如同時支援 v1 與 v2 插件），超出區間時才給出明確的不相容提示。
- **函式表追加式演進**：Native 的 `mpl_host_api_t` 結構體新欄位**嚴格追加在 `ctx` 之後**，禁止在中間插入欄位，舊插件依原有結構體位移定址完全不受影響。
- **ABI 版本防護**：`MPL_ABI_VERSION` 鎖定結構體基礎記憶體配置，僅在發生不相容的破壞性修改時才升級 ABI 大版本。
- **Protobuf 向後相容**：底層通訊採用 Proto3，舊版本客戶端遇到未知的插件訊息欄位時會自動跳過，保證網路通訊平滑相容。
- **凍結標準錯誤代碼**：錯誤代碼 0-12 的語意保持永久穩定，後續僅允許追加新錯誤代碼。

## 3. 安全模型

### Native 插件
- **行程內執行**：Native 插件與宿主共用行程空間，宿主透過能力清單校驗權限。
- **即時安全宣告**：插件透過清單中的 `realtimeSafe: true` 向宿主承諾其符合即時音訊規範，違反規範導致音訊卡頓由插件自行負責。

### WASM 插件
- **記憶體沙箱**：運作在獨立的線性記憶體空間內，無法越界存取宿主記憶體。
- **指令燃料限制**：每次呼叫注入固定燃料預算（預設 100,000），防止無窮迴圈掛起宿主行程。
- **權限逐次校驗**：每次呼叫 Host API 均嚴格比對 `capabilities` 宣告，未授權呼叫回傳 `MPL_ERR_PERMISSION`。

## 4. 效能預算與即時音訊建議

- **DSP 節點耗時預算**：在 48 kHz / 480 樣本幀設定下，每幀時長約 10ms，單個插件節點的平均處理耗時建議嚴格控制在 **1ms 以內**。
- **零鎖競爭設計**：音訊執行緒在處理循環中應避免互斥鎖爭用，設定參數應透過不可分割變數（Atomic）或無鎖讀寫槽傳遞。
- **WASM 定位**：WASM 直譯執行主要面向邏輯編排與輔助處理，重度即時 DSP 推薦使用 Native 撰寫。
